# Safe Exam Browser integration

How exam-taking gets locked down to Safe Exam Browser (SEB), what it costs, and how
the platform verifies a request really came from an untampered SEB session.

---

## 1. What SEB actually gives us

SEB is a kiosk-mode browser. Once a student launches it with a `.seb` config file, it:

- Forces fullscreen, disables Alt+Tab / task switching, kills other running apps, blocks
  screenshot tools, disables the taskbar.
- Disables right-click, browser back/forward, new tabs/windows, dev tools, extensions,
  and clipboard access outside the exam.
- Whitelists which URLs can be reached — nothing outside the exam domain loads.
- Requires a quit password to exit — Ctrl-Q, the Quit button, and the window's close
  button all prompt for it instead of actually closing SEB, so a student can't just back
  out to the normal desktop mid-exam without an invigilator's help.
- Sends a cryptographic proof with every HTTP request (the **Config Key hash**) that lets
  the backend verify the request really came from SEB running the exact, untampered
  config — not a spoofed user-agent string.

That last point is the one piece that needs backend code; everything else is just
configuration in the SEB Config Tool.

---

## 2. Cost

**SEB itself: free, no license fee, ever.** Open source under the Mozilla Public
License, maintained by the SEB Alliance (a non-profit consortium of universities). No
per-seat, per-exam, or per-institution charge for the client, the Config Tool, or the
Config Key verification scheme.

| Item | Cost | Used here? |
|---|---|---|
| SEB client (Windows/macOS/iOS) | Free | Yes |
| SEB Config Tool | Free | Yes — builds the `.seb` file |
| SEB Server (companion app for live-monitoring, centralized config push) | Free, self-hosted | No — not needed, see §6 |
| Third-party webcam/identity proctoring (Proctorio, Examity, etc.) | Paid, separate product | No — not part of SEB, not covered here |

**Platform note:** SEB ships for Windows, macOS, and iOS. There is no official Linux or
Android client — students on Chromebooks or Linux machines can't run it. Any exam with
`requires_seb=true` needs a non-SEB fallback path for them (see §6).

## 3. How the request verification works

1. Every setting in a `.seb` file (URL filter, quit password, kiosk options, etc.) gets
   serialized and hashed with SHA-256 by the Config Tool. That hash is the **Config
   Key** — a single hex string identifying "this exact configuration." The Config Tool
   shows you this value directly.
2. With **Exam tab → "Use Browser Exam Key and Config Key"** ticked, every request SEB
   makes includes:
   ```
   X-SafeExamBrowser-ConfigKeyHash: <hex>
   ```
   computed as `SHA256(requested_url + config_key_hex)`, where `requested_url` is the
   full absolute URL of that specific request.
3. The backend independently computes `SHA256(url + stored_config_key)` for the
   incoming request and compares it to the header. Mismatch (or missing header)
   means either the config was tampered with or the request didn't come from SEB —
   reject it.

Because the Config Key is generated by the Config Tool and handed to you directly, the
backend never reimplements SEB's serialization logic — it just needs the key stored
and a SHA-256 call per request. That's `verify_seb_request()` in `app/seb.py`.

## 4. Building the `.seb` config

Config Tool sidebar tabs, in order: **General, Config File, User Interface, Browser,
Down/Uploads, Exam, Applications, Additional Resources, Network, Security, Registry,
Hooked Keys.**

- **General tab**
  - **Start URL** — see §5 below; it depends on whether this exam uses single-student
    or multi-student login.
  - **Quit/unlock password** — not shared with students.

- **Network tab → Filter**
  - Tick **"Activate URL filtering,"** then add an allow rule for the exam's domain
    (columns: Active / Regex / Action / Expression). Set the default/catch-all action
    to Block if the Config Tool exposes one.

- **Security tab → Kiosk Mode**
  - **"Create new desktop"** — recommended for real exams. SEB and any permitted apps
    run on a separate Windows desktop; switching back to the normal desktop isn't
    possible.
  - **"Disable Explorer Shell"** — closes `explorer.exe` for the duration. More
    invasive, depends on process monitoring; use only if "Create new desktop" doesn't
    fit the lab environment.
  - **"None (for debugging only)"** — no lockdown at all. Only for testing this
    integration, never for a real exam.
  - Also here: disable right-click, screenshots, process switching.

- **Browser tab** — disable dev tools, spell check, links opening new windows or
  navigating off-server, back/forward navigation, cache clearing. Supports the
  lockdown but isn't the enforcement point the backend checks.

- **Exam tab → Browser Exam Key / Config Key** — tick **"Use Browser Exam Key and
  Config Key."** This is what makes SEB send the Config Key hash on every request.
  **Copy the Config Key value shown on this same tab last**, after every other
  setting is final — changing anything above changes the key.

Save as `<exam_id>.seb`, then set on the `Exam` row:
```sql
UPDATE exams SET requires_seb = true, seb_config_key = '<copied key>' WHERE id = '<exam_id>';
```
(No admin UI for this yet — direct SQL is how `requires_seb`/`seb_config_key` get set.)

## 5. One shared config per exam, not one per student

A `.seb` file's Config Key is a hash of **every setting in it, including the Start
URL**. That means the Start URL has to be identical for every student taking a given
exam — bake a personal token into it and you get a different Config Key per student,
but `Exam.seb_config_key` only holds one value. So identity can never live in the
Start URL; it has to be established *after* SEB has already opened, inside its own
window, as something a human types rather than something carried in a link.

This rules out the obvious-looking design of "email a unique link, student clicks it,
SEB takes over" — SEB has no hook into whatever browser opens that link; it's a
separate process with its own storage that can't retroactively lock down a window it
didn't launch. Two Start URL patterns are actually supported:

**Single student, quick tests** — Start URL is that one student's own login-redemption
link (e.g. the magic-link URL). Works, but only for one active student at a time,
since it also pins the Config Key to that one Start URL.

**Multiple students — the real design**:
1. Each student gets emailed a link to `GET /api/invite/redeem?token=...` — a normal
   webpage, opened in a normal browser, showing a short-lived PIN. Redeeming is
   idempotent (every visit just (re-)issues a fresh PIN) specifically so corporate
   mail scanners that pre-visit every link in an email can't burn a single-use token
   before the student ever clicks it.
2. Every student launches the *same* `.seb` file — same Config Key, no per-student
   variation.
3. SEB opens a generic, exam-scoped Start URL (`/pin-login?exam=<exam_id>`) that just
   asks for a PIN.
4. The student types the PIN inside SEB's window. `POST /api/invite/pin-login`
   verifies it and mints a real session the same way magic-link login does
   (`_issue_student_session` in `app/routers/auth.py`) — from here on it's the normal
   Bearer-token flow, and every `/api/exam/...` call passes through the same Config
   Key check as before.

Backed by `ExamInvite` (`app/models.py`) — one row per (exam, student), token and PIN
both stored only as hashes, never in plaintext.

## 6. What this doesn't cover

- **SEB Server** (live-monitoring companion app, centralized config push) and
  **third-party proctoring** (webcam/identity verification) are separate
  products/infrastructure, not part of this integration.
- **Chromebook/Linux students** have no SEB client. Keep a non-`requires_seb` fallback
  exam path for them, relying on the existing advisory signals
  (`ExamAttempt.focus_loss_count`, `ip_address`, `user_agent`) rather than a hard
  lockdown.
- **No admin UI** yet for toggling `requires_seb`/`seb_config_key` on an exam, or for
  triggering the bulk invite send — both are API-only right now
  (`POST /api/admin/exams/{exam_id}/invites` for invites; direct SQL for the toggle).

## 7. Rollout notes

Pilot on one low-stakes exam first. Give students the `.seb` file (or invite email)
at least a day ahead — a first-time SEB install on a locked-down lab PC without admin
rights is the most common support ticket. Confirm the quit password actually blocks
exiting mid-exam, and that the `seb://` launch link behaves correctly on both a clean
Windows and a clean macOS machine before relying on it for a real cohort.
